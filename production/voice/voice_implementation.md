# Bellmont & Co. — озвучка и синхронизация текста
## Технический handoff для ChatGPT Work

**Статус на 29.09.2026:** озвучка текущей сборки подготовлена полностью: **307/307 голосовых реплик**.  
Источник истины для текста и ID: `Bellmont_dialogues_for_voice_current_build(1).md`, собранный непосредственно из текущей игровой сборки `Bellmont_Co_Freight_Box_Victoria_v2.zip`.

Главный принцип проекта:

> **Один ID реплики = один экран диалога = один MP3.**

Например:

```text
VI24-003
текст: "Уверены?"
аудио: VI24-003.mp3
```

Нельзя переименовывать ID, объединять несколько реплик в один аудиофайл или делить одну реплику на несколько аудиофайлов без одновременного изменения системы диалогов.

# 1. Что нужно сделать в Work

Нужно внедрить готовую озвучку в Godot-проект Bellmont & Co. и синхронизировать появление текста с реальной длительностью соответствующего аудиофайла.

## Обязательная логика

1. Каждая отображаемая реплика должна иметь стабильный `id`.
2. По `id` автоматически ищется MP3 с таким же именем.
3. При открытии реплики:
   - предыдущая озвучка останавливается;
   - запускается MP3 текущей реплики;
   - определяется реальная длительность MP3;
   - текст начинает появляться постепенно;
   - скорость появления рассчитывается **из длительности MP3**, а не задаётся фиксированно.
4. Текст должен полностью появиться примерно за **0.15–0.25 сек до конца аудио**.
5. Появление текста должно учитывать пунктуацию: после точки, вопросительного знака, восклицательного знака, запятой и тире нужна небольшая дополнительная пауза.
6. Управление игрока не блокируется озвучкой:
   - если текст ещё печатается, первый клик / нажатие кнопки «Далее» мгновенно показывает всю реплику;
   - озвучка при этом **не обрывается**;
   - если текст уже полностью показан, следующий клик переходит к следующей реплике;
   - при переходе к следующей реплике предыдущий MP3 останавливается.
7. Никаких пользовательских настроек озвучки или скорости текста добавлять **не нужно**.
8. Если для конкретного ID аудиофайл отсутствует, диалог не должен ломаться: использовать запасную скорость появления текста.
9. Не менять текущую верстку диалогового окна и не допускать регрессии, при которой окно или кнопка «Далее» оказываются за HUD.

# 2. Рекомендуемая структура аудио в Godot

На Google Drive файлы разложены по сценам, но внутри игрового проекта удобнее сделать **одну плоскую папку**, потому что все 307 ID уникальны.

Рекомендуемая структура:

```text
res://audio/voice/
    IN0101-001.mp3
    IN0102-001.mp3
    ...
    VI01-001.mp3
    ...
    TO01-001.mp3
    ...
    AM01-001.mp3
    ...
    FR01-001.mp3
    ...
    VI29-008.mp3
```

Тогда путь вычисляется без ручной таблицы:

```gdscript
func get_voice_path(line_id: String) -> String:
    return "res://audio/voice/%s.mp3" % line_id
```

**Не конвертировать MP3 без необходимости.** Godot умеет работать с MP3, а исходные принятые файлы лучше сохранить без дополнительной перекодировки.

# 4. VoiceManager

Рекомендуется вынести проигрывание голоса в единый менеджер, а не создавать отдельную логику в каждом диалоговом окне.

Можно сделать `VoiceManager.gd` как Autoload.

Пример основы:

```gdscript
extends Node

var player: AudioStreamPlayer

func _ready() -> void:
    player = AudioStreamPlayer.new()
    add_child(player)

func get_voice_path(line_id: String) -> String:
    return "res://audio/voice/%s.mp3" % line_id

func has_voice(line_id: String) -> bool:
    return ResourceLoader.exists(get_voice_path(line_id))

func play_line(line_id: String) -> float:
    stop()

    var path := get_voice_path(line_id)

    if not ResourceLoader.exists(path):
        return 0.0

    var stream: AudioStream = load(path)

    if stream == null:
        return 0.0

    player.stream = stream
    player.play()

    return stream.get_length()

func stop() -> void:
    if player != null and player.playing:
        player.stop()

func is_playing() -> bool:
    return player != null and player.playing
```

`play_line()` возвращает реальную длительность MP3, которую диалоговый UI использует для расчёта скорости текста.

# 5. Синхронизация текста с аудио

## Не использовать фиксированную скорость

Плохой вариант:

```gdscript
characters_per_second = 25.0
```

Он быстро рассинхронизируется с реальными голосами.

Нужно рассчитывать длительность отображения так:

```gdscript
var audio_length := VoiceManager.play_line(line.id)

var reveal_duration := max(
    audio_length - 0.18,
    0.20
)
```

Для очень коротких файлов минимальная длительность нужна, чтобы текст не появлялся буквально за один кадр.

# 6. Пунктуация должна влиять на скорость появления

Линейный Tween всей строки допустим как временная реализация, но финальный вариант должен учитывать естественные паузы речи.

Рекомендуемые веса:

```text
обычная буква / цифра         1.00
пробел                        0.25
запятая                       1.8
двоеточие / точка с запятой   2.0
тире                          2.0
точка                         3.5
? / !                         3.5
многоточие                    4.0
```

Это **не секунды**. Это относительные веса.

Алгоритм:

```text
1. Посчитать вес каждого отображаемого символа.
2. Посчитать общий вес реплики.
3. reveal_duration / total_weight = длительность одной весовой единицы.
4. Последовательно открывать символы согласно их весу.
```

Пример функции:

```gdscript
func get_char_weight(ch: String) -> float:
    match ch:
        " ":
            return 0.25
        ",":
            return 1.8
        ":", ";", "—":
            return 2.0
        ".", "?", "!":
            return 3.5
        "…":
            return 4.0
        _:
            return 1.0
```

# 7. Рекомендуемая реализация TextReveal

Лучше не создавать сотни отдельных `Timer` на одну реплику.

Удобнее:
- заранее вычислить массив времён появления символов;
- в `_process(delta)` сравнивать прошедшее время с этим массивом;
- менять `visible_characters`.

Пример структуры:

```gdscript
var reveal_active := false
var reveal_elapsed := 0.0
var reveal_times: Array[float] = []
var reveal_index := 0
var active_label: Label
```

Подготовка:

```gdscript
func start_reveal(label: Label, text: String, duration: float) -> void:
    active_label = label
    active_label.text = text
    active_label.visible_characters = 0

    reveal_elapsed = 0.0
    reveal_index = 0
    reveal_times.clear()

    var total_weight := 0.0
    var weights: Array[float] = []

    for i in text.length():
        var ch := text.substr(i, 1)
        var weight := get_char_weight(ch)
        weights.append(weight)
        total_weight += weight

    if total_weight <= 0.0:
        active_label.visible_characters = -1
        reveal_active = false
        return

    var unit_time := duration / total_weight
    var cumulative := 0.0

    for weight in weights:
        cumulative += weight * unit_time
        reveal_times.append(cumulative)

    reveal_active = true
```

Обновление:

```gdscript
func _process(delta: float) -> void:
    if not reveal_active:
        return

    reveal_elapsed += delta

    while (
        reveal_index < reveal_times.size()
        and reveal_elapsed >= reveal_times[reveal_index]
    ):
        reveal_index += 1
        active_label.visible_characters = reveal_index

    if reveal_index >= reveal_times.size():
        reveal_active = false
        active_label.visible_characters = -1
```

# 8. Клик / «Далее»

Поведение должно быть строго таким:

```gdscript
func on_next_pressed() -> void:
    if reveal_active:
        finish_reveal_immediately()
        return

    VoiceManager.stop()
    show_next_dialogue_line()
```

```gdscript
func finish_reveal_immediately() -> void:
    reveal_active = false

    if active_label != null:
        active_label.visible_characters = -1
```

Таким образом:

### Первый клик во время печати
Только раскрывает весь текст.

### Второй клик
Переходит к следующей реплике и обрывает остаток предыдущего голоса, если он ещё звучит.

Игрок никогда не обязан ждать окончания озвучки.

# 9. Общая функция открытия реплики

Схематично:

```gdscript
func show_dialogue_line(line: Dictionary) -> void:
    VoiceManager.stop()
    stop_current_reveal()

    var line_id: String = line["id"]
    var text: String = line["text"]

    dialogue_label.text = text
    dialogue_label.visible_characters = 0

    var audio_length := VoiceManager.play_line(line_id)

    var reveal_duration: float

    if audio_length > 0.0:
        var end_lead := clamp(audio_length * 0.04, 0.12, 0.25)
        reveal_duration = max(audio_length - end_lead, 0.20)
    else:
        # Только аварийный fallback
        reveal_duration = max(text.length() / 28.0, 0.35)

    start_reveal(
        dialogue_label,
        text,
        reveal_duration
    )
```

# 11. Что делать, если позже меняется текст реплики

Текст на экране и голос должны соответствовать друг другу.

Если текст реплики изменился:

1. сохранить тот же ID, если это всё ещё та же логическая реплика;
2. перегенерировать MP3;
3. заменить файл `<ID>.mp3`;
4. не менять код синхронизации;
5. повторно проверить длительность автоматически — вручную никаких таймингов менять не требуется.

Если новая реплика является отдельным экраном диалога, ей нужен **новый уникальный ID**.

# 12. Отдельный `voice_text` — только при необходимости

Иногда TTS может неправильно произнести:
- сокращение;
- число;
- фамилию;
- название;
- техническую маркировку.

Не надо портить ради произношения видимый текст.

При необходимости в данных можно предусмотреть:

```gdscript
{
    "id": "XX00-001",
    "text": "Видимый текст игроку",
    "voice_text": "Текст, подготовленный только для синтеза речи"
}
```

Но это относится только к **будущей генерации**.

Текущие 307 принятых MP3 уже являются источником истины для текущих реплик и не должны перегенерироваться без причины.

# 13. Настройки генерации голосов

## Важное замечание про «1 в 1»

Runway использует preset TTS-голоса. Одинаковые:
- voice;
- model;
- speed;
- language;
- текст

дают **тот же голосовой тип и очень близкую манеру**, но генерация может иметь небольшую случайную вариативность интонации.

Поэтому:

> **Для абсолютно идентичного дубля нужно хранить и повторно использовать уже принятый MP3.**

Повторная генерация с теми же настройками нужна только для новой или изменённой реплики.

# 19. Нельзя менять при генерации

Для сохранения непрерывности звучания не менять без отдельного нового кастинга:

- language;

# 20. Текст для TTS

По умолчанию в TTS передаётся **точный текст реплики**.

Пунктуация важна, потому что она влияет на интонацию.

Не делать автоматически:
- удаление точек;
- удаление тире;
- объединение предложений;
- добавление многоточий;
- добавление эмоциональных восклицаний;
- переписывание фразы «для красоты».

Если TTS плохо произносит конкретный фрагмент, лучше применить отдельный `voice_text`, чем менять текст игроку.

---

# 21. Проверка новой генерации

Перед добавлением новой реплики в игру проверить:

1. персонаж звучит тем же голосом;
2. скорость речи совпадает;
3. нет неожиданного английского произношения русских слов;
4. нет длинных случайных пауз;
5. нет лишней театральности;
6. голос не стал заметно моложе/старше;
7. весь текст произнесён;
8. начало и конец MP3 не обрезаны;
9. имя файла точно совпадает с ID;
10. MP3 открывается и имеет ненулевую длительность.

# 22. Приоритет источников

При любых расхождениях использовать такой порядок:

1. **уже принятый MP3** — эталон звучания персонажа;
2. текущая карта диалогов из игровой сборки — эталон текста и ID;
3. настройки голосов из этого документа;
4. старые черновики и переписки — только как вспомогательный материал.

Нельзя восстанавливать текст новой реплики «по памяти», если есть актуальная игровая сборка.

# 23. Автоматическая проверка покрытия

После копирования аудио в проект Work должен выполнить проверку:

```text
все voice ID из текущей карты диалогов
MINUS
все имена *.mp3 в res://audio/voice/
```

Результат должен быть пустым.

И обратная проверка:

```text
все *.mp3
MINUS
все voice ID карты
```

тоже должна быть пустой.

Для текущей сборки ожидаемый результат:

```text
voice IDs:  307
MP3:        307
missing:    0
extra:      0
duplicates: 0
```

# 24. Проверка в игре

Обязательно проверить как минимум:

### Интро
- короткую страницу;
- длинную страницу;
- переход «Далее» во время озвучки.

### Ева / Виктория
- короткую реплику вроде «Да.»;
- длинную реплику;
- быстрое пролистывание нескольких строк подряд.

### Томас
- длинную спокойную реплику;
- отсутствие наложения двух MP3 при быстром клике.

### Амелия
- реплику с тире и ироничной интонацией;
- правильное завершение текста до конца голоса.

### Freight Elevator
- несколько коротких реплик подряд;
- быстрый переход между персонажами.

# 27. Ключевое архитектурное решение

Озвучка не должна диктовать структуру диалога.

Правильная зависимость:

```text
dialogue ID
   ↓
visible text
   ↓
MP3 with same ID
   ↓
real MP3 duration
   ↓
text reveal timing
```

То есть при замене MP3 на более длинный или короткий дубль **код менять не надо**: скорость текста пересчитывается автоматически.

Это и есть финальная схема озвучки Bellmont & Co.
